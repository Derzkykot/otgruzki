# Отгрузки винтов

Локальная PWA для iPhone 16 Pro Max. React + TypeScript, IndexedDB (Dexie), ZIP-копии (fflate). Без регистрации, облачной базы и сервера. Планы и фотографии не отправляются в сеть. Входящих демонстрационных данных нет.

## Запуск

Нужны Node.js 22+ и pnpm 11.

```sh
pnpm install
pnpm dev
```

Проверки и готовая статическая версия:

```sh
pnpm test
pnpm build
pnpm preview
```

В `dev` service worker отключён. Офлайн проверяется только после `build`, через `preview` или HTTPS-хостинг. Содержимое `dist/` публикуется целиком, включая `sw.js`, manifest и иконки. Поддерживается размещение в подкаталоге. Серверная часть отсутствует. Нельзя открывать index.html через `file://`.

## GitHub и размещение

Выбран публичный репозиторий GitHub и бесплатный GitHub Pages. Workflow `.github/workflows/pages.yml` проверяет тесты и публикует статическую сборку из `dist`. Базы данных, функции и облачные файловые хранилища не подключаются. Адрес приложения нужно сохранять постоянным: IndexedDB привязана к origin (схема, домен, порт). Инструкция публикации и проверки на iPhone — в [DEPLOYMENT.md](DEPLOYMENT.md).

## iPhone

1. Открыть опубликованный HTTPS-адрес в Safari.
2. «Поделиться» → «На экран “Домой”», затем запустить с иконки.
3. Дождаться «Готово к работе без интернета» в установленном приложении.
4. При желании запросить устойчивое хранение в «Данные»; браузер может отказать.
5. Регулярно сохранять ZIP-копии через «Данные» → «Сохранить резервную копию» → «Сохранить файл» → «Сохранить в Файлы».

При работе в PWA используйте одну установленную иконку. Не полагайтесь на общий набор данных между Safari, приватными вкладками и разными установками. IndexedDB сохраняется между запусками, но не гарантирует защиту от очистки, сбоя устройства, нехватки места или удаления приложения. Резервные копии хранятся отдельно и содержат конфиденциальные документы без шифрования: выбирайте подходящую папку в «Файлах».

Копия — ZIP со всеми данными и фотографиями, версией формата и SHA-256. Восстановление: проверка формата, связей, контрольных сумм и читаемости фотографий → предварительная сводка → подтверждение полной замены → одна транзакция IndexedDB. Восстановление не объединяет базы. При сбое транзакция откатывается. Отмена системного меню не считается сохранением копии.

Ограничение текущей версии: резервная копия до 256 МБ, до 10000 записей архива. Экспорт собирается в памяти, поэтому фактический доступный объём зависит от iPhone. Ошибка копирования не удаляет данные. Фотографии нормализуются в JPEG с качеством 94%, без уменьшения разрешения, до 55 мегапикселей / 30 МБ исходного файла. Читаемость кодов требуется проверить на ваших документах. HEIC зависит от возможности декодирования в Safari; если не читается, используйте JPEG. Снимки с пиктограммой облака в галерее могут требовать загрузки оригинала из iCloud: для офлайн-добавления оригинал должен быть на телефоне.

## Учёт

Количество подтверждается отдельно по каждому типу, включая ноль. Движения требуют подтверждённого прихода. Свободно = пригодно − распределено; отгрузки второй раз не вычитаются. Планирование нехватки разрешено, фактический физический расход сверх прихода запрещён. Для отгрузки сверх заказа сначала увеличьте распределение. Приход на склад и прямые отгрузки — разные движения. Способ выдачи соответствует способу получения в строке клиента. Брак на складе переводит пригодные в брак; брак вне склада можно впоследствии принять как уже учтённый. Дальнейшее движение остатков и брака между партиями, возвраты и утилизация в первую версию не входят.

Ошибки исправляются через историю движений. Сохраняется порядок операций; исправление не может сделать последующие движения невозможными. Поддерживается несколько строк одного клиента с разными способами получения и разными документами.

## Обязательная приёмка на iPhone

Автоматические проверки на компьютере не заменяют этот список:

- Создать Руно и Беркут: правильные типы, новый план без клиентов.
- Добавить клиента: доступен в следующем плане, способ получения выбирается заново.
- Проверить 700 − 200 − 150 = 350; факт 690 → 340; брак 10 → 330.
- Сохранить нехватку и убедиться, что распределение не уменьшилось.
- План 100, передача 60 → остаток 40; свободное количество не изменилось.
- Подтвердить 700; 300 напрямую клиентам, 150 напрямую в ТК, 250 на склад → склад 250.
- Проверить самовывоз: поступление не означает выдачу; брак отделён от пригодных.
- Добавить фото камерой и из галереи; проверить код при увеличении.
- Закрыть PWA, открыть снова: планы, клиенты и фотографии на месте.
- Включить авиарежим, закрыть и повторно запустить PWA: открыть планы, изменить, добавить клиента, локальное фото и движение; перезапустить, проверить сохранение.
- В офлайне подготовить ZIP, сохранить в «На моём iPhone». Отдельно проверить сохранение вручную в iCloud Drive при наличии связи.
- Создать копию с несколькими планами и фото, добавить контрольное изменение, восстановить: точное совпадение с копией и правильные привязки всех фото. Сначала убедиться, что исходная копия действительно доступна в «Файлах».
- Отмена восстановления и повреждённый ZIP сохраняют текущие данные.
- Проверить последний созданный план, закреплённую колонку и горизонтальную прокрутку.
- После публикации новой версии проверить обновление без потери данных.

Фактические проверки на устройстве пока не выполнены.
