# Публикация на GitHub Pages

Выбран бесплатный GitHub Pages с публичным исходным кодом. GitHub хранит только исходники и сборку интерфейса. Планы, справочник клиентов и фото остаются в IndexedDB на iPhone. ZIP-копии не загружайте в репозиторий.

## Первая публикация

1. Создать публичный репозиторий `otgruzki` в своём GitHub, без добавления README и шаблонов.
2. Загрузить текущие исходники в ветку `main`.
3. Открыть Settings → Pages → Build and deployment → Source → GitHub Actions.
4. В Actions запустить `Check and publish PWA` через Run workflow, если первый запуск завершился до включения Pages.
5. Дождаться зелёной задачи `deploy`. Адрес берётся из её результата, а не угадывается заранее.
6. Открыть HTTPS-адрес на iPhone в Safari и добавить на главный экран.

Workflow `.github/workflows/pages.yml` проверяет тесты, собирает PWA, проверяет полноту офлайн-файлов и относительные пути, затем публикует только каталог `dist`. Проверки pull request не публикуются. Личные токены и отдельные серверы не требуются: используются ограниченные встроенные права GitHub Actions.

## После установки

1. Запустить с иконки и дождаться «Готово к работе без интернета».
2. Создать пробный план, клиента и прикрепить фотографию.
3. Закрыть приложение, включить авиарежим и открыть снова. Проверить данные и фото, внести изменение, повторить запуск.
4. Сохранить ZIP через «Данные» → «Сохранить резервную копию» → «Сохранить файл» → «Сохранить в Файлы». Если меню не открывается — «Скачать файл».
5. Убедиться, что файл действительно появился в «Файлах». Восстановить его через приложение, проверить количества и фотографию.
6. После успешной проверки переходить к рабочим партиям.

Используйте один адрес и одну установленную иконку. Нельзя переносить приложение на другой домен в расчёте на автоматический перенос базы. Для переноса используйте резервную копию. У другого приложения на том же домене GitHub Pages технически общий origin: не размещайте рядом недоверенный код, которому не готовы доверить доступ к локальному хранилищу этого домена.

Для обновлений отправляйте изменения в `main`; workflow проверит и опубликует новую сборку. Установленное приложение предложит обновление в разделе «Данные». Перед первым обновлением на реальном iPhone сохраните резервную копию.
